# Mila Vey

Созданный Telegram-бот: https://t.me/MilaVeyChatBot

## Текущий статус

Бот зарегистрирован через BotFather. Код подготовлен и проверен 12 автоматическими тестами с имитацией Telegram/AI. На сервер не установлен: адрес и доступ ещё не предоставлены. Реальная AI-переписка и оплата Stars пока не протестированы. Фото в каталог ещё не загружены. Токен не включён в архив.

## Что реализовано

- Бесплатная переписка через локальную Ollama без платных API и сторонних Python-зависимостей.
- Последние 24 сообщения передаются в контекст, последние 100 хранятся в SQLite. Отдельные факты сохраняются командой /remember; до 30 фактов на пользователя. /memory и /forget.
- Закрытый тест по Telegram ID. Публичный доступ и продажи по умолчанию выключены.
- Приватная админка внутри Telegram: /admin. Доступ только по ADMIN_USER_ID. Регистрация первого посетителя администратором запрещена.
- Загрузка заранее подготовленных фото администратором через Telegram; фото хранятся как Telegram file_id, без копирования на сервер.
- Каталог, цены в Stars, счета XTR, проверка пользователя/суммы/валюты, выдача только после successful_payment, сохранение идентификатора платежа, возвраты.
- После сбоя оплаченные заказы сохраняются для /retry. Повторное уведомление об одном успешно выданном платеже не вызывает новую выдачу.
- При упоминании фото после шести ответов — мягкое предложение каталога максимум раз в сутки. /nooffers отключает предложения. Отказ не блокирует чат.
- /paysupport и /support передают обращение владельцу.
- Работа AI вынесена в очередь: медленная генерация не блокирует подтверждение оплаты.

## Изоляция на сервере

Новый каталог /opt/mila-vey, новый системный пользователь mila-vey, собственный сервис mila-vey.service, собственная база. Без изменений FastPanel, Nginx/Apache, существующих проектов, RunPod или LoRA. Бот использует исходящие запросы long polling: новый публичный порт и домен не нужны. Админка находится в личном чате Telegram.

Python 3.11 или новее. Никаких pip-пакетов. Ollama должна быть уже доступна на loopback с подходящей моделью. Установка Ollama или загрузка модели — отдельный этап после проверки RAM/CPU и нагрузки сервера; не выполняются автоматически. Локальная модель не требует платы за API, но расходует ресурсы сервера. Качество и скорость зависят от модели и оборудования.

## Установка после получения доступа

1. Проверить свободную память, диск, CPU, установленные версии Python и наличие локального AI. Не менять существующие сервисы.
2. Создать отдельного системного пользователя и каталог /opt/mila-vey/data; скопировать bot.py и выставить владельца mila-vey. Не перезаписывать существующий каталог с таким именем без проверки.
3. Создать /etc/mila-vey.env по .env.example (владелец root, режим 600). Внести BotFather BOT_TOKEN и числовой ADMIN_USER_ID владельца, TEST_USER_IDS при необходимости. Не хранить заполненный файл в архиве, переписке или публичном репозитории.
4. Проверить Ollama: http://127.0.0.1:11434, указать имя фактически установленной модели в OLLAMA_MODEL. Скрипт не скачивает модель сам. Внешние AI endpoints кодом запрещены.
5. Установить только новый unit mila-vey.service. Запустить его через systemctl daemon-reload и systemctl enable --now mila-vey. Просмотреть systemctl status mila-vey и journalctl -u mila-vey. Ошибки записываются без токена и текста переписки.
6. Не отключать существующий webhook автоматически: код завершится, если обнаружит подключённый webhook этого бота.

## Обязательный первый тест

Продажи остаются off, public остаётся off. Владелец открывает бота и отправляет /start, затем несколько обычных сообщений. Проверить ответ реальной локальной модели, язык, связность, задержку. /remember Меня зовут Дима; перезапустить только mila-vey.service и проверить /memory и ответ на вопрос об имени. Проверить /forget после завершения очереди AI. Со второго неразрешённого аккаунта проверить отказ в доступе, а также невозможность /admin и /sales on. После успешного бесплатного теста решить, открывать ли public и подключать каталог.

## Админка и фотографии

- /admin — команды; /status — состояние.
- /public on или off — открытие/закрытие чата.
- Пришли фото с подписью `/addphoto 100 Название фотографии`.
- /catalog — список; /hide 1 — убрать фото из новых предложений.
- /sales on или off — продажи. Включать после бесплатного теста и проверки каталога.
- /orders — номера заказов; /retry — повторить выдачу сохранённых оплаченных заказов.
- /refund 3 — вернуть Stars за заказ №3. Это реальный возврат, команда доступна только владельцу.

Настоящие платежи автоматически тестами не производятся. Для следующего этапа — отдельная проверка в официальной тестовой среде Telegram, затем согласованный тест реального платежа. Схема выдачи основана на официальной документации: https://core.telegram.org/bots/payments-stars.

## Ограничения первого выпуска

Одна очередь AI обслуживает сообщения последовательно; для большого числа одновременных пользователей потребуется расширение. Очередь AI в RAM: ожидающие ответа сообщения могут потеряться при перезапуске; сохранённая история и факты сохраняются. При сетевом сбое в момент уже принятой Telegram отправки фото повтор /retry теоретически может прислать вторую копию; новой оплаты он не создаёт. После возврата уже доставленное фото у пользователя не исчезает. Скриншоты и копирование контента полностью запретить невозможно. Приватная админка в Telegram, отдельной веб-админки в этой версии нет.

Создание и хранение локальной модели, резервное копирование базы и проверка её работы требуют доступа к целевому серверу. ChatGPT-подписка сама по себе не предоставляет бесплатный AI API для Telegram-бота.

## Проверки

Из каталога проекта: `python3 -m unittest discover -s tests -v`.
12 тестов: закрытый доступ, админские права, изоляция/сохранение/очистка памяти, интерфейс чата, отсутствие счетов при выключенных продажах, проверки оплаты, дубли платежей, фиксация версии товара, повтор выдачи, запрет внешнего AI, игнорирование групп.
